README — COMPARISON OF UN-ONLY AND ALL-TYPE NRS ASSEMBLIES
============================================================

SHORT DESCRIPTION
------------------------------------------------------------
This pipeline compares two non-reference sequence (NRS)
assemblies generated from the SABE cohort:

  (1) UN-only assembly
      Constructed exclusively from unmapped reads (UN)

  (2) All-type assembly
      Constructed from all discordant read categories
      (UN, HE, SM, and SV)

The workflow evaluates how incorporation of partially
mapped reads affects NRS discovery and assembly structure.
Specifically, the pipeline measures:

- Recovery of UN-derived contigs in the all-type assembly
- Newly discovered sequence introduced by the all-type
  assembly
- Sequence extension and incorporation events
- Assembly restructuring and contig merging
- Differences in contig length distributions
- Differences in population frequencies
- Differences in read support

The resulting analyses were used to quantify the added
value of incorporating all discordant read classes into
NRS assembly.

------------------------------------------------------------
PIPELINE OVERVIEW
------------------------------------------------------------

(1) Compare UN-only and all-type assemblies using BLAST

    Script:
      00_UN_vs_UNHESMSV_blast.py

    Purpose:
      Perform BLAST comparison between the UN-only and
      all-type NRS assemblies.

    Input:
      - UN-only NRS FASTA
      - All-type NRS FASTA

    Output:
      Pairwise contig alignments between assemblies


(2) Classify relationships between contigs

    Script:
      01a_process_alignment.py

    Purpose:
      Process BLAST alignments and classify contigs into
      categories describing how UN-only contigs are
      represented in the all-type assembly.

      Categories include:
      - Near-identical recovery
      - Sequence extension
      - Incorporation into larger contigs
      - Novel sequence
      - Lost sequence

    Output:
      Summary tables describing relationships between
      the two assemblies.


(3) Compare read support between assemblies

    Script:
      01b_Graph_UN_contigs_v2.py

    Purpose:
      Compare maximum per-sample read support for NRS
      assembled using the two strategies.

    Output:
      Histogram of NRS coverage distributions.


(4) Compare contig length distributions

    Script:
      C2_compare_ctg_len_distribution.py

    Purpose:
      Compare length distributions of UN-only and
      all-type NRS assemblies.

    Output:
      Length distribution plots and summary statistics.


(5) Compare population frequencies

    Script:
      A2_compare_expandedreads_freq.py

    Purpose:
      Compare population frequency distributions of NRS
      detected using the two assembly strategies.

    Output:
      Population frequency distribution plots.

------------------------------------------------------------
DECISION RULES
------------------------------------------------------------

BLAST alignment filtering

  High-confidence contig matches are defined using:

    - Minimum sequence identity: 95%
    - Minimum alignment coverage: 80%

Assembly comparison

  Contigs can be classified as:

    - Recovered:
      Near-identical match between assemblies

    - Extended:
      UN-only contig is extended by additional sequence
      in the all-type assembly

    - Incorporated:
      Entire UN-only contig is embedded within a larger
      all-type contig

    - Novel:
      Sequence present only in the all-type assembly

    - Lost:
      No detectable alignment between assemblies

Coverage comparison

  Maximum per-sample read support is used for each NRS
  when comparing coverage distributions.
